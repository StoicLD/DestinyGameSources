# 24 疫病与自然灾害

[返回总览](../README.md) · [设计总纲](../00-framework.md) · [版本](../01-version-and-dlc.md) · [来源索引](../04-sources.md)

## 核心玩法

面对会同时影响人口、人物、财政和统治的危机，选择预防、隔离与恢复方案。识别风险 → 分配防护资源 → 承受冲击 → 处理死亡和治理变化 → 重建。疫病与地震洪水是不同机制，不宜统称为随机扣资源事件。[^1]

## 子机制

| 子机制 | 核心内容 | 玩家取舍 |
| --- | --- | --- |
| 疫病传播 | 疾病在地图地点间扩散，并威胁当地人物 | 监视邻近地区、改变旅行和活动安排 |
| 感染与抵抗 | 地区感染程度和抵抗能力共同影响损失 | 预防性投入与平时经济回报 |
| 医师与防护建筑 | 专业职位与建设提供应对手段 | 保人、保首都或改善更广范围 |
| 隔离与隐居 | 降低部分风险，同时影响正常活动 | 自身安全与持续治理能力 |
| 继承和哀悼 | 人物死亡改变家族与职位；葬礼提供额外活动内容 | 多人连续死亡可能摧毁原有接班计划 |
| 地震、洪水 | 以局势呈现预警、冲击和恢复阶段 | 提前准备还是继续当前战争与建设 |
| 灾后大工程 | 多个角色贡献资源，推进恢复并获得相应收益 | 公共恢复与个人政治收益 |
| 地区联动 | 自然灾害能影响中国王朝循环等系统 | 地方灾害可能演变为中央政治危机 |

疫病基础传播属于 1.12 免费功能；自然灾害和大工程框架属于 1.18 免费功能。相应专属疾病、葬礼和地区项目仍需区分 DLC。[^2]

## 关键决策与设计判断

危机有价值的前提是玩家能看见风险、采取行动，并理解损失原因。灾害可以制造变化，但并非天然优良的反滚雪球系统：弱势玩家也会受灾，随机打击可能进一步放大差距。

恢复阶段尤为重要。它把一次负面冲击变成预算、人事与地方政策的决策链，也允许失败之后继续讲故事。

## 借鉴与最小验证

做一次三阶段洪灾，影响两个地区。玩家选择优先保护首都或粮食产区，并可请求一位封臣共同出资。

验证每种选择是否保留可继续经营的局面，灾后投入是否确实改变恢复时间。不要以无法避免的团灭作为常规事件收益。
