# 22 事件、决议与故事

[返回总览](../README.md) · [设计总纲](../00-framework.md) · [版本](../01-version-and-dlc.md) · [来源索引](../04-sources.md)

## 核心玩法

将世界状态组织为可理解的冲突，让玩家选择，再让结果继续影响世界。读取情境 → 选取符合条件的人物 → 提供有代价的选项 → 修改状态 → 形成下一次事件或行动的前提。[^1]

## 子机制

| 子机制 | 核心内容 | 玩家取舍 |
| --- | --- | --- |
| 条件触发事件 | 因具体行为或状态触发 | 玩家行为得到有意义的回应 |
| 周期事件 | 在一定时间检查条件和权重，再决定是否出现内容 | 给经营过程提供变化，但不能淹没玩家 |
| 事件选项 | 可能受性格、技能、资源、关系和资格影响 | 同一困境有不同解决方式 |
| 决议 Decisions | 玩家在满足条件时主动发起长期或重要行动 | 把模糊愿望变成清晰里程碑 |
| 事件链与故事周期 | 保存参与者和阶段状态，让后续内容延续 | 长期投入与等待、转向之间的取舍 |
| 记忆与关系历史 | 让已经发生的事在人物关系和叙事中留下痕迹 | 往事可以解释现在的友敌 |
| 故事可视化 | 1.19 将宠物、特殊人物故事等显示到故事界面，并展示相关对象和进度 | 长期内容不再完全埋在偶发弹窗中 |

事件页中的通用说明并不覆盖每一种特殊事件。具体目标与状态应以对应玩法模块为准。[^1][^2]

## 关键决策与设计判断

“涌现叙事”来自系统后果与编写内容的组合，不意味着所有故事都由完全自由的生成器创造。很多事件是手写模板，特别之处在于参与者早已与玩家存在关系。

工业化内容生产的关键是稳定的参与者选择、条件、状态更新和文本变体。同一名角色不能同时被抽成互斥身份；已死亡角色、已经离开的配偶或失效的战争目标必须被处理。

## 借鉴与最小验证

做 10 个事件模板，使用实际的家人、封臣和仇敌。每个事件至少影响一项现存关系，并让其中 3 个结果成为后续条件。

让测试者玩完后复述“谁因为哪件事开始反对我”。若只能说“我连续点了十次选项”，说明事件没有写回核心系统。
