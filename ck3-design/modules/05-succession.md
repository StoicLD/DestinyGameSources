# 05 继承与接班

[返回总览](../README.md) · [设计总纲](../00-framework.md) · [版本](../01-version-and-dlc.md) · [来源索引](../04-sources.md)

## 核心玩法

统治者死亡后，将其职位、头衔和部分资产按照制度重新分配。玩家提前判断谁能继承 → 安排婚姻、教育、授地与法律 → 处理死亡引发的交接 → 在新权力结构下恢复稳定。继承既是长期目标，也是反复出现的局势转折。[^1]

## 子机制

| 子机制 | 核心内容 | 玩家取舍 |
| --- | --- | --- |
| 资格与性别法 | 先决定候选人是否有资格 | 一个强大人物未必是有效接班人 |
| 领国继承法 | 决定多个继承人分配，或主要集中给单一继承人 | 稳定集中与制度解锁、亲属利益之间的冲突 |
| 头衔专属继承法 | 部分头衔可具有自己的选举等安排 | 保住关键头衔，不代表所有资产一起跟随 |
| 联盟分割／分割／高等分割 | 以不同方式分配多继承人份额；联盟分割还可能创建可成立头衔 | 活着时扩张的土地可能在死亡时形成新的独立中心 |
| 宣称传递 | 未获得头衔的亲属可能取得相关权利主张 | 下一代内部冲突具备制度依据 |
| 玩家继承与头衔继承 | 玩家继续控制的人、主要头衔继承者与各项资产继承者需要分别看 | 避免用一个“heir”字段代表所有接班结果 |
| 政体特例 | 氏族团结、行政候选评分、营地接班、游牧服从、曼荼罗考验等 | 继承条件本身成为不同政体的核心玩法 |

并非所有法案对所有政体开放。变法也可能受权威、革新、强力封臣态度与共享权力状态限制。[^1]

## 关键决策与设计判断

继承将玩家之前的婚姻、教育、封赏和制度选择集中结算。其价值在于**可预见，但不完全可控**。如果只在角色死亡时突然随机没收土地，玩家难以把失败归因于自己的安排。

典型例子：持有两个同级王国的统治者使用分割继承时，两个子女可能各得一个王国。第二位国王不能仅因为是弟弟，就继续作为同级国王兄长的普通封臣。实际分配仍取决于全部头衔与法律。

## 借鉴与最小验证

做两个继承人、三个头衔、两种继承法和一份可实时预览的分配表。死亡后逐项对照预测，展示头衔、收入、直属关系和宣称如何变化。

首先验证“预览正确、玩家知道哪些结果能改变”。再加入继承人的能力与旧封臣关系。接班是高风险规则，应优先做确定性案例验证。
