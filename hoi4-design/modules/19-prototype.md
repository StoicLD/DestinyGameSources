# 19 最小可玩原型与后续扩展

[返回总览](../README.md) · [系统地图](../00-design-map.md) · [版本边界](../01-version-boundaries.md) · [来源索引](../02-sources.md)

## 要先验证的问题

**军队编制、粮运和可改写的历史目标，能否在小地图上形成互相影响的选择？**

这是下一步实现建议，不是本套文档已经完成的游戏。不要先做整部中国历史、全朝代武器表或大规模战术战场。

## 第一个原型的边界

| 项目 | 建议范围 |
| --- | --- |
| 地图 | 8—12 个地区，1 座仓城，2 个关键渡口／路口 |
| 政治对象 | 玩家势力、原边患势力、可能介入的第三势力 |
| 军队 | 4—6 支可操作单位，3 个预设模板 |
| 编制 | 近战、远射、机动与少量支援职责 |
| 人物 | 主将、副将／替补、军需职责负责人；其余人员聚合表示 |
| 装备 | 两种规格，不做逐部件武器设计器 |
| 补给 | 粮食、通用军需，库存＋在途批次＋共享路线容量 |
| 指挥 | 命令在途、到达、执行；一条简单失联与接班规则 |
| 科技 | 6 个改良／制度节点，有限并行 |
| 历史 | “整顿边防”“粮运危机”两个可适应章节 |
| 战斗 | 自动结算、组织损失、预备队与撤退；不做独立微操场景 |
| 时长 | 目标为一段能在约 20—40 分钟体验的战役，实际需测试调整 |

## 三个阶段

### 1. 规则样机

完成模板—实例、粮仓—线路—部队和历史章节状态。用按钮切换“目标被兼并”“渡口被截”“提前完成目标”，确认世界不会出现非法状态。

完成判据：手工可推导同一结果，粮食守恒，历史章节能正常、替代或结束。此阶段不需要精美地图与大量人物立绘。

### 2. 最小可玩

加入移动、战斗、基础 AI、生产与训练。玩家可通过战争、外交或退守完成一次有结果的战役。

完成判据：至少两种处理路线有合理适用局面；玩家能从界面判断缺额和补给期限；目标变化不靠手工修存档。

### 3. 垂直切片

改善信息呈现、战役节奏、视觉与音效；补齐两条章节的高质量文本和异常结束表现。让没有读过设计文档的人独立试玩。

完成判据：玩家能解释一次成功和一次失败的原因，也能说出某次编制或后勤调整改变了什么。

## 首先要看见的界面

编制界面同时显示纸面需求与实际达成，包含缺额和预计整编时间；补给界面显示粮源、瓶颈、在途到货和可支撑时间；命令界面区分已发出、已收到与执行中。

历史界面显示“为什么现在提出这件事”“什么变化会令它失效”“已经以什么方式解决”。它不应只是看完即消失的弹窗列表。

## 优先延后的内容

完整农业模拟、每辆辎重车微操、全军个人装备、几十种粮秣材料、逐级军官树、全地图复杂最优物流、完整海战、每朝代长国策树和运行时自由生成史实，都可以延后。

围城可以先做有限封锁与补给压力，马匹可以先聚合，军官政治可在军事与历史闭环稳定后接入 CK3 的人物设计参考。

## 下一项扩展如何选择

如果玩家最喜欢粮道攻防，下一步扩展水陆转运与有限地方征粮；如果最喜欢编制，扩展训练适配与支援服务能力；如果最喜欢改史，扩展角色绑定与章节关系。

一次只增加一条经过验证的主线。新模块需要改变已有选择，而不是仅增加一页数值。
