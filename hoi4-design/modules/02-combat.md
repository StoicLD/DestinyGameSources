# 02 战斗结算、组织与撤退

[返回总览](../README.md) · [系统地图](../00-design-map.md) · [版本边界](../01-version-boundaries.md) · [来源索引](../02-sources.md)

## 核心内容

HOI4 把“还有多少人和装备”与“还能否有组织地继续战斗”分开。组织度耗尽可以导致部队退出战斗，并不需要先杀光人员；战宽限制同时投入的兵力，预备队需要进入战斗，地图上的兵多不等于所有兵同时输出。[^1]

## 机制拆解

| HOI4 机制 | 核心作用 | 对古代框架的处理 |
| --- | --- | --- |
| 兵力／装备与组织度 | 分开物质损失和持续作战能力 | 保留；但组织不应成为“士气”的同义词 |
| 软攻／硬攻与硬度 | 按目标机械化构成选择有效攻击 | 不直接平移成步兵／骑兵或轻甲／重甲 |
| 防御／突破 | 守方、攻方分别使用抵御攻击的统计值 | 借鉴进攻时维持秩序的成本，不把突破值等同冲锋伤害 |
| 战宽与多方向进攻 | 限制有效集中，鼓励地形选择和包抄 | 转化为展开空间、道路出口与接敌面 |
| 预备队进入战斗 | 增援不是瞬时参与 | 接入传令、队列、通道和准备状态 |
| 战术与反制 | 将官按资格和权重选择战术 | 由玩家设定偏好，系统根据条件选择 |
| 地形、渡河、筑垒、计划 | 改变同一编制在不同情境下的价值 | 保留结构，重新校准古代参数 |
| 退却、包围与损失 | 失败后的处境决定代价 | 必须区分战术退却、溃逃与无路可退 |

战术选择含随机权重及反制机会，侦察优势不等于每次必然反制。这里没有把 Wiki 的逐项旧系数当作 1.19.2 的完整可执行公式。[^2][^3]

## 建议的战斗状态

第一版保留四类真实状态：人员与装备、组织完整性、疲劳、补给状态。士气可以先并入组织恢复与撤退阈值的参数；只有证明“愿不愿打”和“能否协调”会产生独立决策时，再拆成单独轨道。

可用下列顺序组织每个战斗步长。这是原创结算顺序，不是 HOI4 内部源码描述：

1. 检查双方存活、接敌与继续作战资格。
2. 根据地形和部署，把部队分成参战与预备。
3. 依据真实装备、人员、训练、疲劳和补给，计算可发挥能力。
4. 选择满足条件的战术与应对。
5. 分别结算组织损失与人员／装备损失。
6. 判断脱离、撤退通道、追击与战斗结束。
7. 记录结果，供恢复、军队经验和历史系统读取。

## 几个不宜照搬的抽象

HOI4 的“装甲与穿甲”服务于现代装备对抗。古代护甲、兵器、射击与冲击可有不同作用，但不宜用“骑兵就是坦克”“枪兵就是反坦克”替代设计。应分别看防护覆盖、射程、阵形、地形与训练，并先缩成少数可解释因素。

Wiki 的常规 attrition 主要损失装备与组织，不直接扣除兵员；不能据此宣称 HOI4 已完整模拟行军疾病与饥饿死亡。古代方案若加入伤病、逃亡和运输人员损失，需要自行建立人口去向及恢复规则。[^4]

“包围”也不必立即等于全灭。若仍可藏匿、分散突围或议降，可将它们作为游戏规则中的有限恢复路径；若原型不支持，就清楚地显示被截断的退路与预期后果。

## 可借鉴设计点与验证

最有价值的选择是：现在投入最后一支生力军，还是保留它掩护退却；现在追击，还是停下恢复组织；集中兵力争取局部优势，还是避免挤爆补给。

用同样人数、同样装备，比较平地、窄口、渡河三场战斗；再比较“全部同时投入”与“保留预备队”。没有一种编成在所有情境下无代价占优，才说明地形、组织与支援真正发挥了作用。
