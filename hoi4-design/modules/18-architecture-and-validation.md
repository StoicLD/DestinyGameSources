# 18 模块边界、内容生产与验证

[返回总览](../README.md) · [系统地图](../00-design-map.md) · [版本边界](../01-version-boundaries.md) · [来源索引](../02-sources.md)

## 核心内容

这类游戏最昂贵的部分，是长时间进行中的行动持续遇到世界变化。设计上要避免重复记账、对象失效、信息不同步和历史奖励绕过军队建设。

下文是适合小型项目的实现建议，不是对 Paradox 私有引擎的逆向结论。HOI4 的公开条件接口与补丁中的失效修复，只证明这些问题真实存在。[^1][^2][^3]

## 主责对象与边界

| 对象 | 自己保存什么 | 不应重复保存什么 |
| --- | --- | --- |
| Actor／Polity | 稳定身份、存在状态、政治关系 | 用国号字符串代替身份 |
| Person | 身份、存活、任职与能力 | 把旧职位效果永远绑定本人 |
| Territory | 所有权、控制、通行和据点 | 把政治权属与道路安全合为一项 |
| UnitTemplate | 目标结构、装备准入、支援要求 | 当前部队真实装备 |
| Unit | 实际人员装备、训练、位置、状态 | 所有历史版本模板的重复副本 |
| Command | 发起者、权限、目标、版本、到达与执行状态 | 假定发送即执行 |
| Stockpile／Shipment | 存量、预订、在途、来源去向 | 同一批货在两处都算可用 |
| Knowledge／Adoption | 已知能力与各组织采用情况 | 科研完成等同全国满额部署 |
| HistoricalChapter | 目标、适用范围、生命周期、原始参考 | 写死当前世界必须等于史实 |
| ActionInstance | 绑定对象、费用、有效期、已执行效果 | 用一个全球完成标记处理所有实例 |

初版用少量普通数据结构就能实现，不需要微服务、复杂事件溯源平台或全世界最优流求解。

## 统一的行动边界

所有实际改变都通过少量清楚的操作：调人、配发、发运、接收、任命、下令、签约、宣战、转移控制、完成项目。界面、AI 与历史事件调用同一套资格检查和执行逻辑。

事件可以提出“派出援军”，不能跳过所有人力装备来源直接生成完整军队，除非这条内容明确把来源、成本和例外作为规则的一部分。普通流程与特殊赠与都应有可追踪账目。

## 推荐结算顺序

固定步长中，先处理已到期的有效命令／运输，再结算消耗、行动与战斗，写回世界变化；历史系统随后评估相关章节。具体先后可调整，但必须固定、可解释，并正确处理同一时刻到达和被截的冲突。

随机数使用可保存的种子与状态；待办动作、在途批次和已结算实例进入存档。先做到同一状态可复现，再考虑更复杂的多人同步。

## 优先验证的十二类情境

| 情境 | 检查要求 |
| --- | --- |
| 模板扩大 | 不生成免费的人员装备；需求同步变化 |
| 取消整编 | 已产生的实物与已消耗的训练粮有正确去向 |
| 两军争路 | 同一段容量不被重复使用 |
| 运输被截 | 发货方、接收方、截获方与损耗总量守恒 |
| 部队全灭 | 在途补给按规则改道、退回或失去，不投递给空对象 |
| 将官死亡／换任 | 权限和命令版本更新，不重复叠加岗位效果 |
| 敌情变化 | 报告保持观察时间，不无条件变成实时信息 |
| 历史对象消失 | 已显示提议、进行中动作和候选分别清理 |
| 目标提前完成 | 承认真实成果，不额外执行虚构战争奖励 |
| 弹窗期间换主人 | 最终效果重查，不能割让第三方领地 |
| 重复消息／读档 | 同一实例至多结算一次 |
| 同名政权重建 | 不自动继承过期最后通牒与已领取奖励 |

## 不变量与玩法测试分开

不变量适合自动检查：人数与库存不为负、实物守恒、引用有效、无重复结算、时间不倒流、无越权效果。涉及不同来源合并与永久退出时，要把外部输入和明确损失也纳入账本。

玩法需要实际试玩：玩家能否预测断粮、是否愿意投入支援、旧装备是否仍有用途、历史变化是否被理解、是否存在万能编制。通过账本检查不代表好玩，试玩好玩也不代表长期状态一定正确。

## 内容生产流水线

先写目标与取舍，再定义参与者和硬条件；之后配置合法行动、失效处理和文本。每条重要章节附正常与反事实情景，变更共通规则时优先回跑受影响情景。

规模扩大后再加入“按依赖自动找出受影响事件”、批量种子模拟和更完整调试界面。第一版不要先造一套庞大编辑器，却没有可玩的远征。

## AI 与生成式工具的边界

开发阶段适合辅助生成测试情景、候选文本和配置检查。运行时若使用语言模型，应让它只能从合法候选里建议或润色；不让生成文字直接修改权属、粮食、军队与历史完成标记。

无法用规则解释的错误，不应靠“模型大概理解历史”来掩盖。关键世界状态和执行资格应保持可检查、可复现。
