# 设计总纲：从军事组织到可改写的历史

[返回总览](README.md) · [版本边界](01-version-boundaries.md) · [来源索引](02-sources.md)

## 核心判断

HOI4 最适合本项目借鉴的不是现代兵种表，而是**能力需要被组织出来，军事行动受空间与后勤限制，国家计划通过条件和行动逐步实现**。普通补给、模板、新版支援与 HQ、学说和 AI 路线提供了不同部分的参考。[^1][^2][^3][^4][^5]

古代框架进一步加入真实粮草账本、传令过程和历史目标适应。这些新增不是 HOI4 已完整提供的功能。

## 系统关系

| 输入 | 由什么模块处理 | 输出给谁 |
| --- | --- | --- |
| 政治目标、边患、历史机会 | 历史框架、AI 目标 | 战役任务、改革或外交 |
| 人口、装备、制度许可 | 编制与招募 | 可部署军队及其需求 |
| 科技、制造、训练 | 能力采用 | 实际战斗与支援能力 |
| 粮源、仓储、道路和运力 | 后勤 | 能出征多少人、能坚持多久 |
| 情报、指挥、位置和军力 | 行军与战斗 | 控制变化、损失、经验和新威胁 |
| 战果、关系变化、资源损失 | 世界状态与历史重评 | 下一轮合法目标与选择 |

其中只有世界状态负责“现在真的是什么”。历史章节、AI 判断和界面显示都应读取它，而不各自维护另一套领土、军队或粮草事实。

## 三条循环

**军队建设循环：**确定用途 → 设计编制 → 筹措人员装备 → 训练与配发 → 使用 → 依据损失和经验调整。

**战役循环：**侦察 → 集结与备粮 → 下令 → 接敌／机动 → 消耗与控制变化 → 追击、补充或撤退。

**历史适应循环：**出现相关问题 → 检查当前参与者与条件 → 形成合法选择 → 执行真实行动 → 记录结果 → 解决、替代或生成新的问题。

这三条循环会相互约束：历史上“应该北伐”不能越过粮道已断的事实；编成更多骑乘战兵会改变供养和训练需求；新技术与战场经验可以改变下一轮政策候选。

## 哪些可保留，哪些需重做

| HOI4 设计关系 | 迁移判断 |
| --- | --- |
| 组织与物质损失分开 | 保留；重新定义古代组织、疲劳与士气的边界 |
| 编制模板与现役实例分开 | 保留；非常适合军队建设 |
| 支援单位改变服务能力 | 保留；按人数、负载、装备与岗位划分 |
| 司令部位置与任务关联 | 保留思路；补入授权和传令，不复制现代通讯条件 |
| 干线—枢纽—末端补给 | 保留；改为多粮源、库存、运输时间和守恒 |
| 科研与实际装备采用分开 | 保留；加入工匠、教习与制度普及 |
| 条件化历史路线 | 保留；扩大目标重评和生命周期 |
| 坦克／硬度／空优 | 不直接复制，更不能简单映射骑兵／重甲／哨骑 |
| 连续全国战线 | 按地图尺度重新设计，以据点、通道、军队活动为主 |
| 某日必定发生某场战争 | 不作为默认历史模型 |

## 玩家深度来自哪些取舍

前线多一队战兵，就少一部分支援与运力预算；装备更好，交付和维护可能更慢；战场集中更有力，也更容易超过运输承载；主将靠前更便于作用于关键任务，但风险和其他方向的指挥覆盖会变化。

历史选择应使用同一套代价。接受出征建议，意味着实际征发、筹粮和调动；拒绝也应有与当下政治相关的后果，而不只是少领一个数值奖励。

## 模块不是要求全部同时实现

第一版关键依赖是 [03 编制](modules/03-army-templates.md)、[08 粮草](modules/08-supply-model.md)、[14 历史框架](modules/14-history-director.md)与简化战斗。训练、命令和科技先做最小数据状态；不需要先完成全朝代内容。

具体原型见 [19](modules/19-prototype.md)。军官与 CK3 式关系政治可以后续连接，但不能替代基础战役的可玩性。
